# TASK 16346 — literal brief (follow it exactly; do not explore alternatives)

The issue: https://github.com/tangency-labs/solidcraft/issues/16346

Upstream asked the reporter which fix they wanted, and the reporter chose BOTH
(maintainer comment by Ehuntabi and the reporter's follow-up in the same issue):

1. When the user clicks on empty space in the sketch (a deselect), the arc/circle
   centre point that is currently highlighted must go back to sleep.
2. When the pointer moves too far away from BOTH the arc and its centre point, the
   centre must go back to sleep. The reporter suggested a distance of about 120% of
   the arc radius, measured from the centre point.

What must NOT change: crossing the circle/arc (pointer over empty space between the
edge and the centre) must still keep the centre awake, so the user can walk over the
inside of the circle and click the centre. That behaviour is deliberate and is
covered by an existing test.

## The code you must change (do not rewrite it, do not restructure it)

File: `crates/ui-egui/src/viewport.rs`

- `fn wake_centre(app: &mut SolveApp, hits: &[Hit])` — around line 6925. Today it:
  * when a circle/arc curve is hovered, sets `app.viewport.woken_centre = Some((sketch_id, centre_point_id))`;
  * when a point that is not the woken centre is hovered, clears it;
  * when nothing is hovered (`None` branch), KEEPS it awake (this is the
    "cross the circle" behaviour that must stay).
- The field is `app.viewport.woken_centre: Option<(u64, String)>` (sketch id, point id),
  declared around line 203 in the same file.
- The centre is drawn around line 6902 (the block that paints the cross in a ring) and
  is published to the test harness as the handle `"woken_centre"`.
- The drawing of the woken centre is gated by `previewed != Some(*sketch)`.

Where the pointer is: the viewport already computes, for the sketch under the
pointer, the point under the cursor. Use the same helper the file already uses for
the pointer in sketch coordinates (see `pointer_on_sketch` / `idle_point` in
`crates/ui-egui/src/sketch_cursor_readout.rs` or `crates/ui-egui/src/insert_handles.rs`,
and `crates/ui-egui/src/sketch_transform_ui.rs`); if none of them is reachable from
`viewport.rs`, add a small `pub(crate)` helper in one of those files and call it.
The distance must be measured in SKETCH units (millimetres), not pixels, so that the
"120% of the radius" rule is resolution independent.

The radius of the arc: `crates/sketch/src/model.rs` line ~100, `CurveKind::Arc { c, a, b }`
— the radius is the distance between `c` (centre) and `a` (or `b`). `CurveKind::Circle { c, r }`
carries the radius directly.

## The test you must write (the area's existing test file)

File: `crates/ui-egui/tests/woken_centre.rs` — this file already exists and already
tests this feature (`hovering_a_circles_edge_makes_its_centre_easy_to_take`,
`another_curve_puts_the_centre_back_to_sleep`). ADD your new tests THERE. Do not
create a new test file, do not create a per-bug file.

The file's helpers: `sketch()` builds a sketch with a circle of radius 10 centred at
(20,20) and a line at x=38; `h.step(&json!({"move":{"world":[30,20,0]}}))` moves the
pointer; `h.frames(2)` re-renders; `h.at(&json!({"world":[x,y,0]}))` returns screen
coordinates; `h.app.viewport.woken_centre` is the state to assert on.

Write these tests (names of your choosing, but they must cover exactly this):

A. `the_centre_sleeps_when_the_pointer_leaves_the_arc_and_its_centre`:
   hover the circle edge (world [30,20,0]), assert `woken_centre.is_some()`; then move
   the pointer far away (e.g. world [70,20,0], i.e. more than 1.2 x radius 10 = 12 mm
   from the centre at (20,20)), and assert `woken_centre` is `None`.
   This test MUST FAIL before your fix and MUST PASS after it.

B. `the_centre_sleeps_when_the_user_deselects_by_clicking_empty_space`:
   hover the circle edge, assert awake; then click on empty space far from the circle
   (a world point with no geometry under it, e.g. [70,20,0]), and assert
   `woken_centre` is `None`.
   This test MUST FAIL before your fix and MUST PASS after it.

C. Keep the existing test `another_curve_puts_the_centre_back_to_sleep` passing: it
   moves the pointer from the circle edge (world [30,20,0]) to world [25,20,0], which is
   INSIDE the circle (5 mm from the centre) and must keep the centre awake. Your
   distance rule must not break that case: 5 mm < 12 mm, so it stays awake. If your
   implementation breaks it, your distance is wrong.
