## WHAT IS ALREADY KNOWN (do not redo this)

* The Patch dialog's two inputs are built in `crates/ui-egui/src/dialogs_surface.rs`,
  around line 211:

      Surf::Patch { .. } => vec![
          SelInput::new("Boundary", PROFILES | EDGES, true),
          SelInput::new("Pass through", VERTICES | FACES, true),
      ],

* The accept masks in the issue are the same ones:
  `accept: 3` = `PROFILES (1) | EDGES (2)`; `accept: 132` = `VERTICES (128) | FACES (4)`.

* NEITHER of the two inputs accepts a CURVE. The `CURVES` bit is 256 (see
  `crates/ui-egui/src/selection.rs`, around line 66: "Any sketch curve (a sweep path)").
  Other surface commands DO take curves: `Surf::Boundary` uses
  `SelInput::new("Curves", CURVES | EDGES, true)`.

* `SelInput::accepts` (in `crates/ui-egui/src/selection.rs`, around line 126) is the
  function that turns a `Hit` into a `Sel` for an input; a `Hit` kind the input's
  mask does not accept simply yields `None`, so the click picks NOTHING. That is the
  "the tool does not select the splines" symptom.

* The engine command lives in `crates/engine/src/cmd/` (the surface commands). DO NOT
  touch `crates/kernel`.
