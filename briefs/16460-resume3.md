## THE HYPOTHESIS TO TEST

The pick and the drawing read the model through ONE function,
`crate::open_meshing::shown_world(app)`
(`crates/ui-egui/src/open_meshing.rs`, around line 251):

    pub(crate) fn shown_world(app: &SolveApp) -> Arc<ModelState> {
        let world = session_world(&app.session);
        let Some(m) = app.open_meshing.as_ref() else { return world };
        if !Arc::ptr_eq(&world, &m.world) {
            return world;
        }
        m.shown.as_ref().map(|(_, st)| st.clone()).unwrap_or_else(|| Arc::new(ModelState::default()))
    }

The LAST LINE is the suspect. While a design is being meshed (`app.open_meshing` is
`Some`) and the session's world is the one being meshed, the function answers with
`m.shown` — the PARTIAL model. And when `m.shown` is still `None` (the meshing has
not produced its first chunk yet) it answers with `Arc::new(ModelState::default())` —
an EMPTY model, NOT the session's world.

An empty model means no bodies, no sketches and no profiles to pick. The pick
(`crates/ui-egui/src/viewport.rs`, `pick_hits`, around line 2806) reads
`shown_world(app)`, so with an empty model the pick finds NOTHING — which is exactly
the reported "items: []" and exactly the second reporter's "it prevents me from
selecting ANY EXISTING GEOMETRY as well".

And `open_meshing::tick` (same file, around line 196) is the only place that ends the
meshing:

    if m.finished() && m.shown.as_ref().is_some_and(|(n, _)| *n >= m.world.bodies.len()) {
        ... m.complete = true; ...
        return;
    }
    ctx.request_repaint();

`m.shown` is set to `Some` only when a chunk of meshes arrives (around line 285). For
a world with NO BODIES — a brand new, empty design, which is exactly what "starting a
new Model" gives you — `m.finished()` is true (`done >= bodies.len() == 0`) but
`m.shown` stays `None` forever, so the guard above NEVER fires: `m.complete` stays
false, `m.shown` stays `None`, and `shown_world` keeps answering with the EMPTY
model. The design then stays unpickable and unpaintable until the app is restarted,
which is the reporter's exact symptom.

The "many drawings open" part fits too: `app.open_meshing` is APP-LEVEL, not per-tab
(`crates/ui-egui/src/lib.rs`, field `open_meshing: Option<open_meshing::Meshing>`),
and `documents::switch` does NOT touch it. So switching tabs while another design is
still meshing makes `tick` restart the meshing for the NEW session
(`Meshing::start(world.clone(), ...)`), and if that new session is a brand new empty
design, the trap above is entered.
