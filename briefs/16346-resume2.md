## What is wrong with the click rule — the diagnosis you need

The click handler patch is in `crates/ui-egui/src/viewport.rs`, in the `None =>` arm of
the selection click (around line 6067):

    None => {
        let sel = cand.and_then(|c| c.1);
        // Clicking empty space clears the selection, and the woken centre
        // sleeps with it (#16346): the cross in the ring must not outlive
        // the circle or arc it belongs to.
        if sel.is_none() && !add {
            app.viewport.woken_centre = None;
        }
        select(app, sel.clone(), add, allow_toggle);
        crate::select_other::note_click(app, p, if add { None } else { sel });
    }

The failing test clicks at world [26,20,0]. The circle's centre is at (20,20) and its
radius is 10, so [26,20,0] is INSIDE the circle, 6 mm from the centre.

**The reason the centre stays awake is that the click does NOT reach that `None` arm:
at [26,20,0] the woken centre itself is under the pointer.** The woken centre is
picked from further away than an ordinary point (the constant `WOKEN_CENTRE_PX: f32 =
16.0`), so the click HITS the centre point: `cand` is `Some`, `sel` is `Some`, and the
`sel.is_none()` condition is false. That is also why the test's click does not deselect
anything.

Find this out for yourself and confirm it: print what the click hits (the `Hit` under
the pointer) at world [26,20,0], or read the picking code
(`crates/ui-egui/src/insert_handles.rs`, `crates/ui-egui/src/sketch_transform_ui.rs`
and wherever the woken centre is given its larger pick radius).

Then fix it so that the acceptance criterion holds:

> A click on empty space in the sketch puts the woken centre back to sleep.

The click at [26,20,0] is empty space as far as the user is concerned (there is no
curve and no ordinary point there): the only thing under it is the woken centre
itself, which the woken state made pickable from further away. So the fix has to
recognise "the click hit only the woken centre" as "the click hit nothing", and then
sleep the centre.

Careful, and keep these two behaviours intact:
* clicking ON the woken centre on purpose must still select it (the user takes the
  centre to click it) — the woken centre stays pickable and selectable;
* the pre-existing test `another_curve_puts_the_centre_back_to_sleep` must keep
  passing: the pointer moves from the circle edge (world [30,20,0]) to world
  [25,20,0], which is 5 mm from the centre, so the centre must STAY awake there;
* `hovering_a_circles_edge_makes_its_centre_easy_to_take` must keep passing.

If the cleanest reading is that the click at [26,20,0] should be a DESELECT (empty
space) and therefore the woken centre sleeps with it, then implement that. If you
conclude that the click should SELECT the woken centre and the test's expectation is
wrong, say so in your report and explain why — but the acceptance criterion from the
issue is a click on empty space puts the centre to sleep, so the test should stand.
