## The report (translated from French)

Title: "How to prevent the colouring of a closed zone in a sketch?"

"When a set of lines defines the edge of a closed zone, it gets a pale orange colour.
That is handy if you want to build an extrusion from that sketch later; it should be
possible to enable that by clicking on a button somewhere.

But if you click INSIDE a closed zone that is in ANOTHER SKETCH, while you are in
sketch mode, that zone gets coloured DARK BLUE, and you can no longer see it.

This part of the interface needs to be reworked completely."

Steps to reproduce: "click in a closed zone, when you are in sketch mode".
Version 0.40.1, Windows 10. No screenshot, no recording, no comment on the issue.

READ THE REPORT CAREFULLY: "une autre esquisse" is ANOTHER SKETCH (of the same
design), not another design and not another tab. The person is EDITING one sketch and
clicks inside a closed zone that belongs to a DIFFERENT SKETCH of the same design.

## THE HYPOTHESIS TO TEST (read the code, then test it)

The two colours are two different paints of the SAME profile, and the second one wins.

* The PALE ORANGE is the "closed profile" fill. In `crates/ui-egui/src/viewport.rs`,
  around line 2036-2055, every closed profile of every sketch is drawn filled with
  the theme token `tk.profile_fill`:

      let profile_fill = sc.color(c4(tk.profile_fill));
      for (index, profile) in profiles.iter().enumerate() { ... sc.trans_tri(..., profile_fill); }

* The DARK BLUE is the SELECTED colour: the theme token `t.sel_profile` (and
  `t.sel_profile_edge`). Around line 4525:

      Sel::Profile { sketch, index } if crate::dim_view::previewed_sketch(app) != Some(*sketch) => {
          profile_fill(&mut feedback, app, *sketch, *index, t.sel_profile, t.sel_profile_edge)
      }

  So whenever the session's SELECTION holds a `Sel::Profile`, that profile is painted
  dark blue, ON TOP of the pale orange fill — whatever sketch it belongs to.

Now the question is WHY the selection ends up holding the profile of the OTHER sketch
when the person clicks in sketch mode.

Look at the pick, in the same file, around line 3136-3150: the pick walks
`for sid in sketches.clone()` — every sketch of the session — and offers each of their
profiles as a `Hit::Profile { sketch, index }`. And look at `hit_candidate` (around
line 3680):

    Hit::SketchCurve { sketch, id, .. } if app.session.active_sketch != Some(*sketch) =>
        Some((h.clone(), Sel::ExternalSketchCurve { sketch: *sketch, id: id.clone() }))
    Hit::SketchPoint { sketch, id, .. } if app.session.active_sketch != Some(*sketch) =>
        Some((h.clone(), Sel::ExternalSketchPoint { sketch: *sketch, id: id.clone() }))
    ...
    _ => hit_sel(h).map(|s| (h.clone(), s)),

A curve or a point of another sketch becomes an EXTERNAL selection (named with its
sketch). But a PROFILE of another sketch falls into the `_` arm and becomes
`Sel::Profile { sketch, index }` — a plain selection that does not say it belongs to
another sketch, and that the paint at line 4525 then paints dark blue.

So the defect to test: in sketch mode, a click that lands on a closed zone of a
NON-ACTIVE sketch selects that profile, and the selection paints it dark blue, which
covers the pale orange and makes the zone unreadable.
