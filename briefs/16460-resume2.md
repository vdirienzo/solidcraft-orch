## THE HYPOTHESIS TO TEST (read the code, then test it)

The pick and the drawing read the model through ONE function,
`crate::open_meshing::shown_world(app)`
(`crates/ui-egui/src/open_meshing.rs`, around line 251):

    pub(crate) fn shown_world(app: &SolveApp) -> Arc<ModelState> {
        let world = session_world(&app.session);
        let Some(m) = app.open_meshing.as_ref() else { return world };
        if !Arc::ptr_eq(&world, &m.world) {
            return world;
        }
        m.shown.as_ref().map(|(_, st)| st.clone()).unwrap_or_else(|| Arc::new(ModelState::default()))
    }

Look at the LAST LINE. While a design is being meshed (`app.open_meshing` is `Some`)
and the session's world is the same one being meshed, the function returns
`m.shown` — the PARTIAL model. And when `m.shown` is still `None` (meshing has not
produced its first chunk yet) it returns `Arc::new(ModelState::default())` — an
EMPTY model, not the session's world.

An empty model means: no bodies, no sketches, no profiles to pick. The pick
(`crates/ui-egui/src/viewport.rs`, `pick_hits`, around line 2806) reads
`shown_world(app)`, so with an empty model the pick finds NOTHING at all — which is
exactly "it prevents me from selecting ANY EXISTING GEOMETRY as well", and exactly a
pick with `items: []`.

Now look at `open_meshing::tick` (same file, around line 196). It is the only place
that ends the meshing:

    if m.finished() && m.shown.as_ref().is_some_and(|(n, _)| *n >= m.world.bodies.len()) {
        ... m.complete = true; ...
        return;
    }
    ctx.request_repaint();

`m.shown` is set to `Some` only when a chunk of meshes arrives (around line 285). For
a world with NO BODIES (a brand new, empty design — exactly what "starting a new
Model" gives you), `m.finished()` is true (`done >= bodies.len() == 0`) but
`m.shown` stays `None` forever, so the guard above NEVER fires: `m.complete` stays
false, `m.shown` stays `None`, and `shown_world` keeps returning the EMPTY model.
The design can then stay unpickable and unpaintable indefinitely — until the app is
restarted, which is the reporter's exact symptom.

The "many drawings open" part fits too: `app.open_meshing` is APP-LEVEL, not
per-tab (`crates/ui-egui/src/lib.rs`, field `open_meshing: Option<open_meshing::Meshing>`),
and `documents::switch` (in `crates/ui-egui/src/documents.rs`) does NOT touch it.
So switching tabs while another design is still meshing makes `tick` restart the
meshing for the NEW session (`Meshing::start(world.clone(), ...)`), and if that new
session is a brand new empty design, the trap above is entered.
